How I test

Eight steps, in order. Select a step to see what I do in it.

  1. Requirement analysis

    Read the requirements and list what can be tested.

    I note unclear or missing requirements and ask about them before writing any tests.

    Show details

  2. Test planning

    Decide scope, approach and exit criteria.

    I set what is in and out of scope, which types of testing to run, and when testing counts as done.

    Show details

  3. Test case design

    Write positive, negative and edge cases.

    Each case has a clear precondition, steps and an expected result so anyone can run it.

    Show details

  4. Test data and setup

    Prepare accounts, data and environment.

    I gather the data each case needs, such as valid and invalid users, before execution starts.

    Show details

  5. Test execution

    Run each case and record the result.

    I compare actual with expected results and mark every case as passed or failed.

    Show details

  6. Defect analysis

    Reproduce failures and find the cause.

    I narrow down when and why a failure happens so developers can fix it quickly.

    Show details

  7. Bug reporting

    Log bugs with evidence and priority.

    Every bug gets steps to reproduce, expected and actual results, screenshots, severity and priority, tracked in Jira.

    Show details

  8. Closure and review

    Summarise results and lessons.

    I report coverage, open bugs and what to improve in the next test cycle.

    Show details
